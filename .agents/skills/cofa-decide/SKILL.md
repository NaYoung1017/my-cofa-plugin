# cofa-decide — 결정 기록

제출 뒤 설명은 결정 기록과 실제 코드에서 나온다. 기록은 **사용자가 나중에 AI 없이 읽고 설명할 수 있는** 말로 쓴다.

## 언제 쓰나
- 사용자가 선택지 중 하나를 골랐을 때 (방식, 범위, 데이터 처리, 우선순위)
- 담당자 답 때문에 요구나 방향이 바뀌었을 때
- 사용자가 AI의 제안이나 결과를 고치거나 거절했을 때 → `[수정]` 형식
- 이전 결정을 바꿀 때 → 새 항목 "D-n 정정", 옛 항목은 지우지 않는다
명령 하나, 단순 수정, 이름 바꾸기 같은 것은 기록하지 않는다.

## 일반 형식 (10줄 이내)
```
## D-n. (짧은 제목)
- 결정자: 사용자 | 사용자(AI 제안 채택) | 담당자 조건 | README 조건
- 근거: 담당자 Q-n / README / 데이터 이슈 I-n / 시간 제약
- 내 말: "(사용자가 말한 이유·조건 그대로. 없으면 비움)"
- 선택: 무엇을 어떻게
- 대안: (버린 것) → 버린 이유
- 이유: 업무에 어떤 영향이 있어서
- 적용 조건: 이 선택이 맞는 입력·규모·상황
- 한계 / 재검토 조건: 약점과, 무엇이 바뀌면 다시 볼지
- 코드: 파일:함수 (아직이면 "예정")
- 검증: V-n PASS | FAIL | NOT_RUN
```

## [수정] 형식 (AI 제안을 고치거나 거절한 경우)
```
## D-n. [수정] (짧은 제목)
- 계기: 무엇을 보고 이상하다고 느꼈나 (화면 / 담당자 말과 다름 / 실행 결과)
- 내 요청: AI에게 어떻게 수정을 요청했나 (한 줄)
- AI 제안: 처음 내놓은 것
- 받아들인 것 / 바꾼 것 / 뺀 것:
- 근거: Q-n / README / 실행 결과
- 확인: 고친 뒤 무엇을 실행해 확인했나
```

## 규칙
- 결정자를 정확히 쓴다. 사용자가 고르지 않은 것을 "사용자"로 쓰지 않는다. AI가 정한 것이 남아 있으면 사용자에게 확인받기 전까지 "미확정"으로 둔다.
- "내 말"은 사용자가 대화에서 실제로 한 말만 옮긴다. 다듬거나 지어내지 않는다. 비어 있으면 기록 뒤에 "이유를 한 줄 남기시겠어요?"라고 한 번만 묻는다.
- 비교하지 않은 대안을 비교했다고 쓰지 않는다. 실행하지 않은 검증은 NOT_RUN.
- 이유에는 기술적 이유보다 **업무 영향**(누가 무엇을 덜 틀리고, 덜 기다리나)을 먼저 쓴다.
- 한계에는 "무엇이 바뀌면 이 선택을 다시 볼지"를 꼭 넣는다.
- 기록한 뒤 사용자에게 한 줄만 알린다: "D-n 기록: (제목)". 사용자가 고치라고 하면 고친다.

## 끝나면
다른 스킬 중간에 불렸으면 그 스킬의 다음 단계로 돌아간다. 단독으로 불렸으면 이 결정 때문에 다시 볼 것을 추천한다.
`👉 다음 추천: (이 결정으로 영향받는 작업 / 스킬) — 이유`
