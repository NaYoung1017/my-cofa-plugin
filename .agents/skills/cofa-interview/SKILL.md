# cofa-interview — 담당자 질문과 답 기록

담당자는 한 번에 답을 주지 않고, 물어본 범위 안에서 맥락과 방향만 알려준다. 그래서 **열린 업무 질문에서 시작해 구체적인 조건으로 좁혀가는** 대화가 필요하다. 질문을 보내는 것은 사용자다.

## 모드 1 — 질문 만들기

1. `cofa-notes/BRIEF.md`에서 처리가 `확인 필요`이거나 `질문`인 모르는 것(U-n)·데이터 이슈(I-n), 추론 출처 요구, `INTERVIEW.md`의 꼬리 질문을 **전부** 모은다. 이미 답을 받은 것만 뺀다.
2. 지금 대화가 어느 단계인지 보고 다음 칸의 질문을 만든다(모든 칸을 다 물을 필요는 없다).

   | 단계 | 묻는 것 | 예 |
   |---|---|---|
   | ① 현재 업무 | 누가, 어떤 순서로 하고 있나 | "지금 이 일은 누가 어떤 순서로 처리하나요?" |
   | ② 최근 사례 | 곤란했던 구체적인 사례 하나 | "최근 가장 곤란했던 경우를 하나 설명해 주실 수 있나요?" |
   | ③ 우선순위·비용 | 어느 실수가 더 큰 피해인가, 무엇이 먼저인가 | "A가 늦는 것과 B가 틀리는 것 중 어느 쪽이 더 문제인가요?" |
   | ④ 입력·기대 결과 | 구체적인 값, 경계, 예외 | "기준값과 정확히 같은 경우는 포함하나요?" |
   | ⑤ 이해 확인 | 내가 이해한 것을 되묻기 | "그러면 A를 우선하고 B는 이번에 제외하는 것으로 이해해도 될까요?" |

3. 질문 모양: **대상 하나 + 구체 상황 + 열린 질문 (필요하면 선택지)**.
   - 데이터가 지시서와 어긋나면: 어디서 몇 건이 어긋나는지 사실을 먼저 말하고, 실무에서는 어느 쪽을 우선하는지 묻는다.
   - 피할 질문: "뭘 만들면 되나요?", "할 일을 순서대로 알려주세요", "어떻게 구현하나요?", "주의할 점 있나요?" 같은 막연한 질문, 초반의 해법 단어("AI로 자동화", "최적화 알고리즘").
4. 모은 항목 전부를 질문 후보로 만들어 `INTERVIEW.md` "질문 후보" 표에 영향도 순으로 적는다. 각 질문에 연결 항목(U-n / I-n)과 "답에 따라 무엇이 바뀌나" 한 줄. 같은 대상에 대한 항목은 한 질문으로 묶을 수 있지만 연결 항목은 모두 적는다.
5. 담당자는 한 번에 많이 물으면 답이 흐려지므로 **이번에 보낼 것 최대 3개**를 추천한다. 나머지는 대기열로 **전부 보여준다**(한 줄씩). 빼지 않는다.
6. 사용자가 고르고 직접 보낸다. 다듬어 달라고 하면 고친다. 사용자가 질문하지 않기로 한 항목은 BRIEF 처리 칸에 "가정으로 진행(내용)" 또는 "영향 없음(이유)"을 사용자 말대로 적는다.

## 모드 2 — 답 기록 (사용자가 답을 붙여넣으면)

1. `INTERVIEW.md` "주고받은 기록"에 Q-n으로 쌓는다: 보낸 질문 / 답(숫자·고유명사 그대로) / 조건 / 예외·단서 / 영향 / 꼬리 질문.
2. 담당자가 규칙을 말하면 그 규칙의 **예외**를 묻는 꼬리 질문을 하나 제안한다. 단서 하나로 결과가 뒤집히는 경우가 많다.
3. 영향 판단: 이 답 때문에 바뀌는 요구(R-n), 데이터 이슈 처리, 기존 결정(D-n)을 짚는다.
   - 바뀌는 것이 있으면 사용자에게 "이 답 때문에 ___이 바뀝니다. 반영할까요?"라고 묻고 멈춘다. 반영은 `$cofa-align`에서 한다.
   - 사정만 들은 경우 "영향 없음"으로 적는다.
4. BRIEF의 연결 항목(U-n / I-n) 처리 칸을 `Q-n`으로 바꾼다. 답이 불충분하면 `확인 필요`로 둔다.
5. 남은 `확인 필요` 개수(높음/중간/낮음)를 함께 알린다.

## 끝나면
- 질문을 만든 뒤: `👉 다음 추천: 담당자에게 질문 보내고 답을 붙여넣기 — $cofa-interview 로 기록`
- 답을 기록한 뒤 (아래 중 해당하는 것 하나):
  - 답 때문에 요구·방향이 바뀌면: `$cofa-align — 바뀐 내용 반영`
  - 영향도 높음 `확인 필요`가 남아 있으면: 다음에 보낼 질문 하나 추천
  - 높음이 모두 처리됐으면: `$cofa-align — 방향 정리 후 계획으로`

## 하지 말 것
- 담당자에게 사용자 대신 질문을 보내기
- 답에 없는 조건을 추측으로 채우기 (모르면 "미확인 → 꼬리 질문")
- 질문 수 늘리기 자체를 목표로 삼기, 반대로 확인할 항목을 말없이 빼기
- 답을 받자마자 코드를 고치기 (반영 여부는 사용자가 정한다)
