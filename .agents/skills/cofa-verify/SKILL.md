# cofa-verify — 돌려서 확인하기

"실행됨"과 "맞음"은 다르다. 실제 출력만 증거다.

## 1. 요구별 검증
1. `BRIEF.md` 요구 표에서 dropped가 아닌 R-n을 모두 가져온다.
2. 요구마다 VERIFY 표에 V-n을 만든다. 경로는 해당하는 것만:
   - 정상: 실제 사용 흐름 하나가 끝까지 도는가
   - 실패: 빈 데이터, 필요한 값 누락, 형식 오류, 권한 없는 사용자
   - 경계: 기준값과 같은 값, 0건 결과, 최대치
3. 기대 결과는 손으로 계산할 수 있는 작은 입력으로 정한다. 데이터 처리 결과는 원본에서 몇 건을 직접 뽑아 대조한다.
4. 명령으로 확인할 수 있는 것은 실제로 실행하고 결과를 그대로 적는다. 실행하지 않았으면 `NOT_RUN`.
5. 화면은 사용자가 플랫폼 브라우저에서 직접 확인한다. 브라우저·화면 자동 조작 도구(Computer Use 등)는 쓰지 않는다. 화면이 있는 요구마다 최소 하나씩 "사용자가 직접 눌러볼 것" 체크리스트를 만들어 주고, 사용자 확인 결과를 받아 적는다.
6. FAIL이 나오면 원인 가설과 수정 방향 선택지를 내고 멈춘다. 고친 뒤 실패했던 입력과 관련 정상 입력을 다시 실행한다.
   사용자가 고치지 않고 한계로 두기로 정하면 `$cofa-decide`로 D-n을 남기고(결정자: 사용자) 판정을 `FAIL(한계 D-n)`으로 바꾼다. 제출 문서의 한계에도 적는다. 사용자가 정하지 않은 FAIL을 이 형식으로 바꾸지 않는다.
7. (선택) 시간이 20분 이상 남았으면 `$cofa-delegate`로 `cofa-reviewer` 전체 검수를 제안할 수 있다(대상 "전체", 핵심 요구 R-n 위주). 그동안 메인은 2·3단계를 한다. reviewer의 FAIL은 메인이 재현한 것만 VERIFY에 올린다.

## 2. 제출물 확인
`BRIEF.md` "제출 요구"의 항목마다 VERIFY "제출물 확인" 표에 S-n을 만든다.
- 파일이 README가 정한 이름·위치에 실제로 있는가 (`ls`로 확인)
- 산출물 예시·형식 파일이 있으면 필드·열 이름·순서·파일 형식이 같은가
- 실행 방법이 요구된 경우 README대로 실행하면 실제로 뜨는가
없거나 형식이 다르면 FAIL과 같이 다룬다: 무엇이 빠졌는지 보여주고 만들지·고칠지 사용자가 정한다. 형식 파일 원본은 고치지 않는다.

## 3. 보안 점검
- 역할별 권한: 다른 역할의 기능·데이터에 접근하는 요청을 직접 보내서 막히는지 본다.
- 개인정보: 화면·API 응답·로그에 필요 이상의 값(주소·연락처 등)이 나오지 않는가.
- 비밀값: `python3 .cofa/tools/check.py` 결과의 비밀키 스캔.
- 입력 검증: 빈 값·형식 오류·범위 밖 값을 넣었을 때 안내가 나오고 서버가 죽지 않는가.
요구에 없는 보안 기능을 새로 만들지 않는다. 문제가 있으면 수정안을 제안하고 사용자가 정한다.

## 4. 마무리 점검
1. `python3 .cofa/tools/check.py`를 실행한다. exit 0 정상 / 1 문제 있음 / 2 검사한 항목 없음(통과 아님).
2. 처음부터 다시 실행해도 동작하는지(서버 재시작, 새 터미널) 한 번 확인한다. 웹 서버면 README가 정한 포트(지정이 없으면 3000)로 `0.0.0.0`에 떠 있는지 `curl http://localhost:<포트>`로 확인한다.
3. 사용자에게 보고: PASS / FAIL / 한계 / NOT_RUN 개수와 함께 FAIL·한계·NOT_RUN 항목, OK가 아닌 제출물(S-n), check.py의 FAIL·WARN 항목, 처리가 `확인 필요`로 남은 U-n·I-n을 **전부** 나열한다. 확인하지 못한 것은 이유를 붙인다.
4. 이 시점부터 **기능 추가는 하지 않는다.** 남은 시간은 `$cofa-explain`과 제출 문서에 쓴다.

## 끝나면
- FAIL이 있으면: `👉 다음 추천: (가장 영향 큰 FAIL) 수정 — 선택지를 보고 고르기` (시간이 없으면 한계로 기록하는 선택지도 함께)
- 제출물이 없거나 형식이 다르면: `👉 다음 추천: (S-n) 제출물 만들기·맞추기`
- 원본 파일 변경이 잡혔으면: `원본 복구 여부 확인 — (파일)`
- 모두 처리됐으면: `$cofa-explain — 동작 방식 정리와 제출 문서 맞추기`
